# Design: Virtual Desktop management

## Context and verified boundaries

- The current composition root (`bootstrap.py`) constructs one `LocalPvmAdapter`, `CollectionCoordinator`, application facade, `SessionManager` and `OperationCoordinator`. Textual `PlaividTui` has Overview and VM tabs; it owns one timer, queues blocking reads in workers, drops wrong-session results by epoch, and keys VM selections by UUID. Desktop state should follow these patterns rather than spawning a parallel service or polling each Desktop.
- `LocalPvmAdapter._call` uses `SbellClient.call(module, command, params, token)` with a default-deny credential-argv gate, bounded local child execution and typed errors. `list_objects` is VM-specific. The operator verified the separate Lite Desktop `user/objects` query on PVM 7.1.26, but supplied a representative object body rather than a redacted full response envelope. Preserve the literal query and reject unverified field interpretations.
- VM actions use `_action_params(Action, uuid)` and `dispatch_action` invokes **`vm/<action>`**, not `pvmm`. `OperationCoordinator` admits only fresh `VMRecord`s from its VM object/inventory sections and binds approvals to that inventory generation. This cannot safely be called with an arbitrary Desktop UUID or a forged `VMRecord`.
- The supplied web-client requests show `/sabad-plaivid/vm/stop` with bare `<vm_key>UUID</vm_key>`, `/sabad-plaivid/vm/pause` (no payload shown), and a `vm_start` body with `<vm_key>UUID</vm_key><host>auto</host><version_start>...`. Docs `SBELL-SABAD.md` §§2, 4, 8 explicitly state `sabad` and local `sbell` use the **same module/command and XML params**; HTTP `version=1.0.0`, empty `query`, cookies and multipart boundaries do not become sbell arguments. This establishes the mapping to existing `sbell vm stop` and `sbell vm start` payload shapes (the pasted start body did not include its URL), but the request lacks response status and proof that this UUID is a Lite Desktop rather than an ordinary VM. Do not enable Desktop mutation until that applicability is confirmed.

Illustrative **VM command shapes only, not commands to run against a Desktop before action-specific approval** (use the configured sbell executable; the session token remains subject to the existing argv-exposure acknowledgement):

```bash
sbell vm stop '<vm_key>DESKTOP_UUID</vm_key>' 'SESSION_TOKEN'
sbell vm pause '<vm_key>DESKTOP_UUID</vm_key>' 'SESSION_TOKEN'
sbell vm resume '<vm_key>DESKTOP_UUID</vm_key>' 'SESSION_TOKEN'
sbell vm reset '<vm_key>DESKTOP_UUID</vm_key>' 'SESSION_TOKEN'
sbell vm kill '<vm_key>DESKTOP_UUID</vm_key>' 'SESSION_TOKEN'
sbell vm start '<vm_start><vm_key>DESKTOP_UUID</vm_key><host>auto</host><version_start><version_enable>no</version_enable><version_vkey></version_vkey></version_start><exit_from_replicate>yes</exit_from_replicate></vm_start>' 'SESSION_TOKEN'
```

The capture gives a `/vm/pause` route but no Pause XML or result. Resume, Reset and Kill have only VM reference implementations; their Desktop applicability is **unverified**. The angle brackets shown as `&lt;`/`&gt;` in the pasted HTTP capture represent XML characters, not literal escaped text to send to sbell.

## Data flow and types

1. Define a `VirtualDesktop` model separate from `ObjectVM`: canonical full UUID, name, object `type`, optional `is_enabled`, `ha_enabled`, timestamps, parent_id, `local_status`, `cluster_status`, cluster host, OS type/version/architecture, parsed vCPU and raw RAM size with explicit unit uncertainty. Preserve identifiers for selection; shorten UUID **only** for display. Distinct properties must not overwrite each other. Owner/Zone are optional, evidence-gated projections from `xobj_connection` (`cname=perm`/`parent`), not fabricated defaults.
2. A pure `parse_virtual_desktops(description)` walks only matching `pvm_desktop_obj` elements of type `pvm_desktop_lite_virtual_desktop`. Empty `<objects/>` is a successful empty result. Missing optional elements yield `None`/N/A. Reject malformed UUIDs; detect duplicate UUID groups and exclude ambiguous records, reporting partial quality. A missing required wrapper/description or malformed outer response is an error/unavailable result, never success=zero. Reuse the safe vCPU computation (`socket × core × thread` only if all positive) without guessing units for memory. XML names/fields are read locally; no per-object calls.
3. A narrow read gateway method invokes `user/objects` once with the exact owner-verified query, current session token and existing `_require_read`/redaction behavior. Extend the collection coordinator with an independent `virtual_desktops` section, generation, status/last-good and single serialized read lane. Do not conflate this section with VM `objects` or `inventory`, or include it in VM mutation freshness barriers.
4. Add a read-oriented application facade to request the section. The TUI schedules reads only when the Desktop page is visible (plus explicit Refresh/after an accepted action), coalesces with the existing busy/pending mechanism, invalidates on logout/session epoch and uses no per-row fetch. Keep the existing Overview and VM cadences intact. Set an explicit cadence during implementation/review; do not treat the Overview's 1–60s local-host setting as permission to hammer PVM.

## UI

A third `TabbedContent` page, **Virtual Desktops**, uses existing Textual theme tokens and a narrow/wide layout. Toolbar: Refresh, name search (`Input`), a six-action dropdown and explicit **Apply to all Desktops** checkbox (single selection otherwise); list: name, short UUID, type, cluster runtime status, OS type/version, calculated vCPU and raw RAM only with a verified unit label; Owner and Zone columns are conditional on verified `xobj_connection` mapping, otherwise N/A. At 80 columns prioritize Name, Status, OS and short UUID; retain full UUID, enablement, local status and cluster status in the detail panel. Do not call `is_enabled` a runtime state. A neutral or warning text label remains visible when color is absent. The selected row is tracked by full UUID across sorting/filter/refresh and selection clears when it disappears. Empty, loading, partial, stale, error and unsupported-action states show distinct text; filter is local and does not send a new PVM request on every keystroke. Update only changed rows/widgets rather than clearing or redrawing the entire screen. Keep keyboard Tab/arrow/Enter navigation and add an explicit Desktop-page shortcut without replacing existing `1`/`2` bindings.

## All six actions and bulk scope: gated design, no speculative dispatch

The Desktop page mirrors the VM action menu: Start, Resume, Pause, Stop, Reset and Kill, for the selected Desktop or all Desktops. Each action has an independent capability/evidence gate: a verified Lite Desktop UUID, route, XML params, success envelope and allowed transitions. The supplied Stop and Start shapes are candidate `sbell vm` calls; the Pause route alone and VM-only references for Resume/Reset/Kill are **not** Desktop proof. Keep controls disabled or return an explicit unsupported reason with zero calls for every unapproved action. Do not let Start/Stop evidence implicitly enable the other four.

After each gate is approved, use **full canonical Desktop UUIDs**, a typed Desktop-target plan bound to a current complete Desktop section and freshness limit, and the existing session/risk/approval/outcome semantics. Do not forge VMRecord instances or pass Desktop UUIDs through the VM-specific `_build_plan` and object inventory barrier. Extract shared plan, mutation-lane and reply-handling mechanisms or extend them safely. For bulk, require a configured positive `PLAIVID_MAX_INVENTORY_AGE_SECONDS` plus a complete, freshly collected Desktop listing. The action and complete ordered UUID set/count must be inspectable before confirmation; approvals bind to those UUIDs and the Desktop generation. Preserve the existing high-risk single-target confirmation rules and bulk confirmation for **every** action. An active name filter does not silently redefine "all": Apply to all means the unfiltered current Desktop inventory; make this scope conspicuous and reject ambiguous/empty selections. Recheck generation/freshness at dispatch; never operate on a row index or name.

Execute bulk sequentially in the existing serialized mutation lane and stop further dispatch on definite failure or unknown outcome, showing unattempted targets. After accepted or uncertain outcomes, request a single Desktop-list reconciliation through the shared read lane, without per-object read calls or claiming a completed state transition from command acceptance. Maintain logout/session-epoch barriers and typed error/redaction behavior. No extra actions beyond the existing six without a new proposal.

## Risks / alternatives

- The supplied request XML matches documented VM Start/Stop shapes, but it might be for an ordinary VM UUID; no successful Desktop response was provided. Pause has only a route and the remaining three actions have no Desktop request examples. Do not enable any Desktop dispatch solely from VM documentation or captured requests. Do not try `desktop/start|stop` or `pvmm` without evidence.
- Treating `parent_info/parent_id` as a zone label, or `perm` connection as an owner username, is unverified. Render a verified raw ID if useful, otherwise N/A; do not infer names.
- Empty list is distinct from a failed read. A partial list may be displayed with warning but cannot authorize mutations. Status, refresh age and source remain visible.
- Keep existing TTY-only launch and `NO_COLOR`/256-color fallbacks. No added server-side packages, agent, SSH, credential output, or one-request-per-Desktop pattern.

## Verification plan

Use a redacted, versioned full response fixture plus synthetic minimal/multiple/empty/duplicate/invalid XML; fake gateway checks the exact single query, token gating, and errors; collection tests cover single-flight, section isolation and logout races; Textual Pilot checks 80/120 widths, search, keyboard selection, detail, empty/error/stale state and no per-row calls. Operation tests first assert **zero dispatch for each unverified action**. After each action gate is cleared, add selected/all UUID-vs-name, filtered bulk scope, admission/approval, partial failure/unknown/stop-and-reconcile tests with its verified route/params fixtures, followed by separately authorized non-production PVM acceptance. Run full suite, Ruff, Pyright, build and strict OpenSpec validation; record any Python-version limitations rather than claiming unsupported coverage.
